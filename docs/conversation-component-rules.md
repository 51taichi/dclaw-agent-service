# DClaw 会话组件与 Agent 返回规则

> 规则版本：1.22
> 最后更新：2026-10-23
> 适用范围：DClaw Agent Service、管理后台预览、智能名片、官网客服、小程序 WebView、Agent Gateway

## 1. 文档定位

本文档是会话组件的产品与协议规范，是以下实现的共同依据：

- Agent Gateway 告知 DClaw Agent 当前可用的展示能力。
- Agent 返回文字、卡片建议和结构化交互结果。
- Service 校验、降级、存储和投递 Agent 返回内容。
- 官网、智能名片和小程序渲染会话内容。
- `/components/` 展示组件的默认、交互和完成状态。

DClaw Agent 不应感知 CSS、HTML 或具体渠道页面结构。它只处理语义组件类型和结构化数据；DClaw Agent Service 持有组件清单、Schema、使用规则、渲染方式和降级策略。

### 1.1 智能名片跨端一致性

- 管理后台预览、Web 名片和小程序名片使用同一份渠道与人物配置，Web 成品页面是视觉验收基准。
- 二维码统一使用页面内自定义弹层，不调用各端原生图片预览；遮罩、卡片尺寸、关闭按钮、标题和提示文案保持一致。
- 公司反面的视频按整张名片画布裁切，统一使用 `cover` 和顶部居中的视觉锚点；隐藏的背面不得提前初始化视频，避免小程序原生媒体层加载失败。
- 正反面切换按钮统一采用 54px 视觉尺寸，并允许用户沿右侧上下拖动调整位置。
- 切换按钮上方显示当前目标身份名称；正面指向公司助手，反面指向个人员工。名称标签使用与右下角翻转徽标一致的蓝底白边样式，居中压在头像上沿；两者都不得被按钮裁切。
- 公司反面的首屏内容使用弹性高度填满视频场景与语音栏之间的空间，快捷入口随可用高度伸展，不允许在卡片与语音栏之间留下大块无意义空白。
- 正面展开/收起分隔线与半圆按钮必须有轻微重叠，避免不同像素密度下出现透明接缝。

### 1.2 官网人物入口与 Web 名片

- 官网客服第一层只负责展示公司吉祥物和当前渠道已部署的人物列表，不维护独立的官网聊天窗口。
- 访客点击某个人物后，必须在官网浮层内打开该人物的 Web 名片；正反面、联系方式、会话区、输入栏、快捷提问、留资和会话组件与智能名片使用同一渲染器。
- 人物资料属于智能员工，不属于任何渠道。官网和智能体名片都读取同一份人物资料；会话、消息、状态机、标签、计费和 Agent 路由继续使用当前渠道部署及其 Channel Adapter，禁止跨渠道读取配置或切换账号。
- 官网外层允许调整浮层尺寸、停靠位置、打开和关闭方式；名片内部的结构、样式、组件状态与交互规则不得另行复制实现。
- 名片左上角返回按钮在官网浮层内返回人物列表；从列表切换人物时必须重新加载对应人物及其官网部署上下文，不得沿用上一个人物的会话身份。
- 管理后台 iframe 预览与公开官网植入页面必须走同一路径，确保人物列表和 Web 名片切换效果一致。

### 1.3 后台配置与发布

- 管理后台草稿是预览页的唯一业务配置来源；已发布配置是公开 Web 名片和小程序名片的唯一业务配置来源。
- 客户、公司、人物相关名称、品牌文字、头像、背景、联系方式、欢迎语和快捷内容不得在客户端按名称重写。
- 前端只允许提供通用产品兜底文案；后台明确配置的值必须原样生效。视频地址明确留空时表示使用静态助手形象，客户端不得补回演示视频。
- 渠道只维护公共展示效果和公司助手配置；智能员工在人物页通过开关启用一个或多个渠道，渠道不能依赖人物，也不能依赖另一个渠道。
- 人物名片资料在人物层统一维护，各渠道只允许保存明确登记的少量展示覆盖；当前版本不提供人物渠道覆盖表单。
- Agent API 配置统一在平台 Agent 配置库维护，平台必须且只能指定一个默认 Agent。智能员工和渠道公司助手默认继承该 Agent；只有打开各自的独立绑定开关后，才保存显式 Agent 绑定。公司助手不属于智能员工，名片正反面也不是 Agent 配置的分类属性。
- 后台渠道预览使用“张三”占位展示公共效果；智能员工预览必须使用该员工真实资料与所选渠道，并通过 iframe 加载最终渲染页面。
- 后台预览中的真实 Agent 对话必须标记为 `admin-preview` 或 `admin-preview-assistant`，便于统计侧排除测试数据。
- `voiceEnabled=false` 时，正面语音切换入口、公司反面语音输入栏和相应录音交互必须同时隐藏。
- 正面人物与反面公司助手必须使用同一套真实录音链路：按住开始、上滑取消、松开发送；录音文件先上传为 `audio` 附件，再进入各自独立的会话与 Agent 绑定，禁止用固定“语音提问”文本模拟录音。
- Web 端麦克风依赖浏览器安全上下文，只保证 `HTTPS` 与本机 `localhost` 可用；局域网 HTTP 真机测试应使用原生小程序录音能力，不得把权限失败误报为 Agent 故障。
- 后台保存只更新草稿；只有执行“发布配置”后，公开 Web 和小程序接口才读取到新值。
- 首屏不得注入演示期固定选择题。单选、多选和留资组件应由状态机、Service 规则或经过校验的 Agent 返回触发；后台配置的快捷问题除外。

## 2. 总体决策顺序

组件决策必须遵循以下优先级：

```text
状态机明确指定
    ↓
Service 业务规则确定
    ↓
Agent 根据语义建议
    ↓
Service 校验数据和渠道能力
    ↓
不符合规则时降级为普通回答
```

通用约束：

1. 一轮最多展示一个要求客户提交的交互组件。
2. 单选、多选、留资表单不能在同一轮同时出现。
3. 普通文字回答可以附带资料列表或一个富链接卡片。
4. 状态机指定组件后，Agent 无权更换组件类型。
5. Agent 只能从 Service 提供的能力白名单中建议组件。
6. Agent 不得返回任意 HTML、CSS、JavaScript 或未登记的组件类型。
7. 文件、图片、链接和联系方式必须有真实数据来源，禁止 Agent 编造。
8. 无法判断、数据不完整或当前渠道不支持时，统一降级为普通回答。

## 3. 组件分类与控制权

| 组件 | 控制方 | Agent 是否可建议 | 主要用途 |
| --- | --- | --- | --- |
| 回答卡片 `assistant-response` | Service 自动 | 否 | 展示 Agent 的所有普通文字回答 |
| 客户消息 `message` | 渠道与 Service 自动 | 否 | 展示客户发送的文字或结构化交互结果 |
| 语音消息 `voice-message` | 渠道自动 | 否 | 展示实际发送或接收的语音 |
| 单选 `single-choice` | 状态机优先 | 是 | 客户必须从固定选项中选择一项 |
| 多选 `multi-choice` | 状态机优先 | 是 | 客户可以选择多个固定选项 |
| 留资表单 `lead-form` | 状态机或 Service 规则 | 是，需校验 | 收集经过客户同意的结构化联系资料 |
| 资料列表 `resource-list` | Service 优先 | 是 | 同时展示多个真实资料或文件 |
| 富链接卡片 `card` | Service 优先 | 是 | 展示一个真实网页、案例或活动入口 |
| 快捷问题 `suggestion-chips` | 首屏由渠道配置，后续由 Service 控制 | 是，仅建议问题文本 | 首屏或阶段性推荐问题 |
| 操作按钮 `action-button` | 组件内部 | 否 | 提交选择、提交表单或执行明确动作 |
| 图片和文件附件 | 实际资源决定 | 是，需校验 | 展示已生成或已检索到的真实资源 |

并非组件目录里的所有组件都开放给 Agent。消息渲染器、基础按钮和快捷问题属于 Service 或渠道能力。

## 4. 回答卡片

### 4.1 使用规则

- Agent 的普通文本 `reply` 自动使用回答卡片。
- Agent 不需要显式返回 `assistant-response`。
- 回答卡片不显示 Agent 身份、大小标题或多余角色说明。
- 客户文字不能使用回答卡片，必须使用右侧客户消息气泡。

### 4.2 底部操作

| 操作 | 规则 |
| --- | --- |
| 复制 | 复制当前回答正文，并提供成功或失败反馈 |
| 朗读 | 使用系统语音朗读；再次点击停止；结束后取消高亮 |
| 有帮助 | 高亮“赞”，并取消同一卡片的“踩” |
| 没有帮助 | 高亮“踩”，并取消同一卡片的“赞” |
| 分享 | 优先调用系统分享；不支持时复制回答和页面链接 |
| 重新生成 | 正式会话请求 Agent 重新生成；组件页只演示加载与完成反馈 |

赞与踩互斥，均可再次点击取消。所有图标按钮必须有 tooltip、`aria-label` 和可识别的激活状态。

## 5. 单选与多选

### 5.1 使用场景

- 单选用于只能选择一个固定答案、且选择后才能继续的场景。
- 多选用于允许同时选择多个固定答案的场景。
- 开放式问题、建议列表或不完整选项不能使用选择组件。
- 两种组件都必须由客户点击右下角“提交回答”后才算完成。

### 5.2 页面状态

选择前：

- 选项可操作。
- 未选择任何内容时提交按钮禁用。
- 选中项使用蓝色边框、背景和居中的白色勾号。

提交中：

- 禁用选项和提交按钮。
- 按钮显示“提交中...”。
- 等待 Service 确认，不能提前标记成功。

提交成功：

- 原选择卡片保留在会话历史中并变为灰色锁定状态。
- 已选项目保留灰色实心勾选，未选项目保持空框。
- 按钮显示“已提交”。
- 会话右侧新增客户消息气泡，显示客户可读的答案，例如“业务咨询、案例资料”。
- 后续 Agent 回答显示在客户气泡之后。

提交失败：

- 保留已选择内容。
- 恢复可操作状态。
- 按钮显示“重新提交”并给出失败提示。

### 5.3 结构化事件

页面显示客户可读气泡，Service 同时接收结构化结果：

```json
{
  "type": "choice-response",
  "componentId": "service-needs",
  "mode": "multiple",
  "values": ["business", "cases"],
  "labels": ["业务咨询", "案例资料"]
}
```

Agent 必须能够知道这是哪个组件的回答，不能只收到脱离上下文的普通字符串。

## 6. 留资表单

### 6.1 允许触发

触发优先级：

1. 状态机进入预约联系、商务合作、获取方案等明确需要联系方式的节点。
2. 客户主动点击“联系负责人”“预约沟通”等入口。
3. 客户明确表达“请联系我”“安排人员沟通”“我想合作”等意图后，Agent 建议展示，并由 Service 校验。

### 6.2 禁止触发

- 普通问候、一般咨询或仅查看资料。
- 客户没有表达联系意愿。
- 当前会话已经成功留资，且客户没有要求更新资料。
- Agent 无法确定客户是否同意被联系。

### 6.3 提交状态

提交成功后：

- 表单变为灰色锁定状态，按钮显示“已提交”。
- 表单历史中的联系方式必须脱敏，例如 `138****5678`。
- 右侧新增客户气泡“已提交联系信息”，不展示完整手机号或微信号。
- Service 创建独立留资记录，并按配置添加标签、提醒或人工跟进任务。
- Agent 收到结构化 `lead-submission` 事件后回复确认信息。
- 页面刷新后仍保持已提交状态。
- 需要修改时使用“更新联系信息”，不重复生成新表单。

提交失败时保留填写内容，恢复按钮，并允许重新提交。

### 6.4 隐私与协议

完整联系方式不得作为普通聊天文字放入客户气泡，也不得无约束地拼入 Agent Prompt。Service 应单独存储并按权限提供：

```json
{
  "type": "lead-submission",
  "componentId": "contact-form",
  "fields": {
    "name": "张先生",
    "contact": "13800138000"
  },
  "consent": true
}
```

## 7. 资料、链接与附件

- 一个具体网页、案例或活动入口使用富链接卡片。
- 两个及以上相关真实资料使用资料列表。
- 一个普通文件直接使用文件附件，不为其额外包装资料列表。
- 图片必须有可访问的真实地址和安全的替代文本。
- Service 校验 URL 协议、渠道能力和资源归属；校验失败时不渲染可点击资源。

## 8. 快捷提问

- 快捷提问不是每条 Agent 回复的必需内容。
- 首屏可以展示渠道配置的固定问题；进入会话后，可以根据当前回复、状态机节点和最近对话动态更新。
- 只有在问题能明显降低客户输入成本或帮助进入下一步时才展示，否则返回空数组。
- 每组建议展示 1–3 条，文案必须短、明确、可直接作为客户问题发送。
- 不得重复当前客户刚刚提出的问题，不得提供与当前上下文无关的问题。
- 快捷提问区域必须显示“快捷提问”标题，让客户明确知道下方内容可以点击。
- “快捷提问”标题和全部选项始终位于同一横排；可视宽度不足时横向滚动，禁止换到第二行。
- 点击后，该问题作为一条客户消息进入会话；当前组随即失效，不能在后续上下文中重复提交旧建议。
- Agent 只建议问题文本，Service 负责数量限制、去重、敏感操作过滤和最终展示。

## 9. Agent 能力告知与返回

Service 应在每次 Agent 请求中附带当前渠道的展示能力，而不是依赖长期记忆或只写一段模糊提示词：

```json
{
  "presentationCapabilities": {
    "schemaVersion": 1,
    "defaultReplyComponent": "assistant-response",
    "allowedAttachments": [
      {
        "type": "single-choice",
        "usage": "客户只能从完整的固定选项中选择一项"
      },
      {
        "type": "multi-choice",
        "usage": "客户可以选择多个固定选项"
      },
      {
        "type": "lead-form",
        "usage": "客户已明确同意留下联系资料"
      }
    ]
  }
}
```

Agent 返回示例：

```json
{
  "reply": "请选择您希望了解的内容",
  "attachments": [
    {
      "type": "single-choice",
      "id": "service-entry",
      "title": "请选择",
      "options": [
        { "label": "业务咨询", "value": "business" },
        { "label": "方案梳理", "value": "solution" }
      ],
      "submitLabel": "提交回答"
    }
  ]
}
```

Service 必须校验类型、字段、选项数量、真实资源和当前渠道能力。Agent 建议不等于最终渲染指令。

## 10. 消息输入区

- 输入框为空时，展示图片、文字/语音切换和更多功能入口。
- 用户输入有效文字后，输入区切换为专注发送状态：隐藏图片、语音和更多入口，输入框占满剩余宽度，右侧只显示蓝色圆形向上箭头发送按钮。
- 用户清空输入内容、发送成功或发送动作已进入处理流程后，输入区恢复为空状态的工具入口。
- 进入专注发送状态时必须自动收起已经展开的“更多功能”面板。
- 文字模式从左至右固定为“相机、文字输入框、麦克风、更多”；点击麦克风只切换输入模式，不能直接开始录音。
- 语音模式从左至右固定为“相机、按住说话、键盘、更多”；点击键盘显式返回文字模式。
- 用户按下“按住说话”后才开始录音；按住期间显示录音时长和“松开发送，上滑取消”，上滑超过取消阈值后切换为取消状态。
- 松开后发送有效语音并生成客户语音气泡；上滑取消或录音短于 350ms 时不发送。成功发送后保持语音模式，除非用户点击键盘切回。
- 微信小程序在渠道启用语音时，首次打开名片即主动申请 `scope.record` 麦克风权限；不得等到用户长按后才首次申请。
- 用户曾拒绝麦克风权限时，系统授权框不能再次直接弹出，页面必须说明用途并引导用户进入微信设置重新开启；切换语音模式和开始录音前仍需校验权限。
- 权限申请成功发生在一次长按手势期间时，本次手势不得自动开始录音，必须提示用户重新按住，避免松开事件丢失后持续录音。
- Web、管理后台 iframe 预览和 uni-app 微信小程序使用同一状态规则、控件顺序与视觉尺寸，不得分别实现不同交互。

## 11. 名片正反面切换入口

- 正面展示员工人物与人物 Agent，反面展示公司吉祥物与公司 Agent；悬浮头像用于切换正反面。
- 点击悬浮头像执行翻面；沿右侧边缘上下拖动只调整入口位置，不能触发翻面。
- 拖动范围必须避开顶部小程序菜单和底部消息输入区，横向位置保持固定。
- 用户调整后按渠道在本地保存相对位置；视口尺寸变化时按相对位置重新计算并限制在安全范围内。
- 鼠标和触屏使用相同规则，触屏拖动入口时不得带动会话页面滚动。
- 展开态的职务与公司名称位于头像右侧同一行，显示为“职务 · 公司名称”，公司名称不再单独占用一行。
- 展开态联系方式使用一条连续的半透明栏；各项均以图标加值展示，不显示重复的文字标签。
- 联系方式最多两行：配置联系二维码时，第一行展示官网、邮箱，第二行展示地址、电话，二维码作为第二行末尾的固定宽度入口。
- 已配置联系二维码时不再重复展示微信号；微信字段继续保留在人物配置中。未配置二维码时，微信号可作为普通联系方式展示。
- 联系方式两行使用同一主分隔基准：第一行官网与邮箱之间的分隔线，必须与第二行地址与电话之间的分隔线纵向对齐。
- 联系方式容器使用轻度透明的深色底和克制的背景模糊，让头图可以透出，同时保持图标和文字的可读对比度。
- 二维码入口使用透明背景和固定宽度分栏，只让二维码图片本身保留白底；禁止把整个二维码按钮渲染成白色块。
- 二维码缩略图必须可点击放大；放大层在当前名片内居中展示，并支持关闭按钮、点击遮罩和 `Esc` 关闭。
- 每项内容保持单行，超长值使用省略号，不得撑宽名片或影响下方会话组件。
- 展开/收缩按钮必须与头图底部的横向分隔线共用同一条连续描边：横线在中心抬起形成无底边的上半圆，左右端点与半圆两端精确连接，不能让横线穿过按钮或与按钮错层。
- 头图底部不叠加额外的渐变或模糊遮罩；展开/收缩箭头固定为白色，并在半圆轮廓内垂直居中。

## 12. 公司吉祥物助手背面

- 名片正面使用人物绑定的 Agent，背面使用当前渠道公司助手绑定的 Agent；两者未显式绑定时都继承平台唯一默认 Agent。背面展示配置属于渠道级配置，不写入单个人物，正面或反面也不构成 Agent 配置的分类。
- 人物 Agent 与公司吉祥物 Agent 必须共用唯一的会话组件库、结构化协议、样式和交互状态，不允许公司侧单独复制或维护回答卡片、客户气泡、选择、留资、资料及附件组件。
- 两侧可以不同的只有场景外壳、人物或吉祥物身份、主题配置、快捷入口和 Agent 路由；同一种会话组件接收同一份数据时，渲染结果与提交行为必须一致。
- 背面初始态必须是全屏吉祥物语音助手，展示公司吉祥物、欢迎语、环绕快捷话题、两组快捷项目和底部语音入口。
- 吉祥物形象、欢迎语、环绕话题、两组项目的标题与条目、语音按钮文案和提示文案都必须由后台渠道配置提供。
- 点击环绕话题、快捷项目或完成语音输入后，初始内容保留在长页面上方；页面在其下方追加客户消息和 Agent 回答，不能用会话内容替换初始场景。
- 每次触发先追加一条右侧客户消息气泡，再追加一张完整的 Agent 回答卡片。后续互动继续按时间顺序追加，形成同一条长滚动会话。
- 进入会话态后，顶部显示吸顶返回栏；点击“返回全屏吉祥物语音助手”回到页面顶部并恢复初始态，但不删除本次会话记录。
- 底部语音栏在初始态和会话态均保持可见；会话滚动时固定在可视区域底部，不随消息离开屏幕。
- 管理后台 iframe 预览、公开 H5 和 uni-app 微信小程序必须消费同一渠道配置和会话组件协议，避免预览样式和最终交付样式分叉。
- 公司助手初始页允许配置一条竖屏循环背景视频。视频作为整页视觉底层，话题、项目卡片、会话与语音按钮仍由可访问、可交互的页面组件覆盖，禁止把业务文案和点击热区直接烘焙进视频。
- 推荐视频比例为 `9:16`，使用 MP4(H.264) 或 WebM，静音、自动循环并启用 `playsinline`；后台单文件限制为 30MB。
- 视频加载失败、浏览器禁止播放或用户启用“减少动态效果”时，页面必须自动回退到渠道配置的静态吉祥物形象和渐变背景。
- 视频、图片及浮层共同覆盖完整首屏，快捷项目区与语音栏之间不得出现无意义的纯白占位区域。

## 13. 变更同步要求

任何会话组件规则变化必须在同一次修改中同步检查：

1. 更新本文档的规则版本、最后更新日期和相关条目。
2. 更新 `public/components/cards.js` 的共享渲染器。
3. 更新 `/components/` 中对应的默认、交互、成功、失败或禁用状态演示。
4. 更新 Agent Gateway 的能力清单、Schema、校验和降级规则。
5. 更新官网、智能名片和小程序对结构化事件的处理。
6. 增加或更新自动化测试，确保预览与公开页面使用相同组件。

不得只修改某个渠道页面的局部样式或只修改 Agent Prompt，而不更新本文档和共享组件。
